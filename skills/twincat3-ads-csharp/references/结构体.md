# 结构体（UDT）的 ADS 读 / 写 / 通知 —— 实测记录

> 2026-10-18 本机实测（`127.0.0.1.1.1:851`，`Beckhoff.TwinCAT.Ads` 7.0.172 / net8.0）。
> 作者测试 PLC 工程（未随技能提供）：
> - `MAIN.ST1 : stAxisInput`（`AT%M*`，816 字节）
> - `MAIN.arrSt : ARRAY[1..3] OF stAxisInput`（`AT%M*`，2448 字节）
>
> 探针：`scripts/ads-struct-probe/`（`dotnet run -- MAIN.ST1 [--notify|--write|--mem|--arr]`）。
> 本文所有偏移 / 数值都是**实际跑出来的**，不是按类型推的。

## 一、结构体在符号表里长什么样

`SymbolLoaderFactory.Create(client, SymbolLoaderSettings.Default).Symbols` **只返回顶层容器**：

```
顶层符号 5 个：Global_Version / GVL_AdsDemo / GVL_Test / MAIN / TwinCAT_SystemInfoVarList
```

这 5 个的 `Category` 都是 `Struct`、`ByteSize = 0` —— **它们不是结构体实例，是容器**。
真正的结构体实例要**递归 `SubSymbols`**，按 `Category == Struct && ByteSize > 0` 过滤。
递归后本工程找到 10 个实例，其中 `MAIN.ST1` 是我们建的测试结构体。

`MAIN.ST1` 的元信息（`IAdsSymbol`）：

```
TypeName = stAxisInput   Category = Struct
BitSize = 6528           ByteSize = 816
IsBitType = False        IsByteAligned = True
IndexGroup = 0x4020      IndexOffset = 405152
成员 36 个，每个成员都有自己的 IG / IO
```

**成员 ByteSize 合计 798，结构体 ByteSize 816 → 18 字节填充**：

| 位置 | 填充 |
|---|---:|
| 53–55（`bLimitSenser` 后，下一个 LREAL） | 3 |
| 123–127（9 个 BOOL 后，下一个 LREAL） | 5 |
| 145–151（`bReversingStart` 后，下一个 LREAL） | 7 |
| 485（`arrString` 后，WSTRING 数组要 2 字节对齐） | 1 |
| 814–815（末尾按 8 对齐） | 2 |

**推论**：BOOL 是 **1 字节**（`BitSize=8`）；`STRING(n)` = n+1 字节；
`WSTRING(n)` = 2n+2 字节（`STRING(80)` = 81，`WSTRING(80)` = 162）。TwinCAT 按自然对齐排布。

## 三、三种读法

| 读法 | 结果 |
|---|---|
| `CreateVariableHandle("MAIN.ST1")` | ✅ 返回 `0x60000010` |
| `Read(0xF005, h, buf)` | ✅ 返回 816 字节 |
| `ReadAny<byte[]>(h)` | ❌ `MarshalException: Cannot marshal dotnet type 'Byte[]' because its marshal size is unknown!` |
| `ReadValue(path, typeof(byte[]))` | ✅ 816 字节（库从符号信息拿到长度） |
| `IValueSymbol.ReadValue()`（结构体符号） | ✅ 返回 `Byte[]`，816 字节 |
| `ReadAny<StAxisInput>(h)` | ✅ 需要 C# 布局逐字节匹配 |

句柄读到的原始字节（开头，对应默认值 10 / 100 / 10）：

```
0000000000002440  0000000000005940  0000000000002440
        10.0                100.0                10.0
```

## 四、C# 结构体怎么接（`ReadAny<T>`）

最终可用定义（`LayoutKind.Sequential, Pack = 8`）：

```csharp
[StructLayout(LayoutKind.Sequential, Pack = 8)]
struct StAxisInput
{
    public double lSetPos1;      // 0
    public double lSetPos2;      // 8
    // ... 省略中间同名字段 ...
    public byte bReset;          // 160
    [MarshalAs(UnmanagedType.ByValArray, SizeConst = 324)] public byte[] arrString;         // 161
    public byte alignPad;        // 485 —— WSTRING 数组的 1 字节对齐，必须手写
    [MarshalAs(UnmanagedType.ByValArray, SizeConst = 324)] public byte[] arrAxisModeString; // 486
    public byte bWavebusy;       // 810
    public byte bWaveDone;       // 811
    public byte rLimit;          // 812
    public byte lLimit;          // 813
    // 814-815 由 Pack=8 自动补齐
}
```

实测：

```
Marshal.SizeOf<StAxisInput>() = 816  （PLC 侧 816）
lSetPos1=10  lSetPos2=100  dSelectMode=1  iCycleNumber=1
lHomeOffset=200
arrString         = 0.1s | 0.3s | 0.5s | 0.8s
arrAxisModeString = 单轴模式 | 群控模式
```

**坑**：

- **不能用 `LayoutKind.Explicit` + `byte[]` 字段** → 运行时
  `TypeLoadException: contains an object field at offset 161 that is incorrectly aligned or overlapped by a non-object field`。
- C# 默认 `Pack=8` 与 TwinCAT 的自然对齐一致，**不要手写 `Pack=1`**。
- 必须拿 `Marshal.SizeOf<T>()` 和符号的 `ByteSize` 对；不相等就别用 `ReadAny<T>`。
- 对齐填充不能“按成员大小累加”推 —— 用符号表里每个成员的 `IndexOffset` 核对。

## 五、整块写（`WriteAny<T>`）

实测（改 `lSetPos1/lSetPos2/dSelectMode/bWavebusy`，其余字段不动）：

```
写前快照：lSetPos1=10 lSetPos2=100 dSelectMode=1 bWavebusy=0
整块写后回读：lSetPos1=111.11 lSetPos2=222.22 dSelectMode=2 bWavebusy=1
```

**★ 整块写是“覆盖”，不是“合并”**：

```
1. 单独把 lSetPos1 写成 333.33        → 333.33
2. 拿改动前的旧快照整块写回            → lSetPos1 变回 111.11
```

即：816 字节里没打算改的字段也会被快照里的旧值覆盖。
→ 结构体里有 PLC 也在写的成员时，**写前立刻重读合并**，或只逐成员写。

结构体里的数组元素可以单独写（按符号名，逐元素）：

```
WriteValue("MAIN.ST1.arrString[1]", "0.9s")
WriteValue("MAIN.ST1.arrAxisModeString[2]", "维护模式")
```

## 六、Ex 通知订阅整个结构体

```csharp
plc.AdsNotificationEx += OnEx;
var settings = new NotificationSettings(AdsTransMode.OnChange, 0, 0);
uint nh = plc.AddDeviceNotificationEx("MAIN.ST1", settings, "ST1", typeof(StAxisInput));
```

实测：

```
AddDeviceNotificationEx(MAIN.ST1, …, typeof(StAxisInput)) = 0x2
通知#1  handle=2  value=(lSetPos1=10    lSetPos2=100 dSelectMode=1 bWavebusy=0)
通知#2  handle=2  value=(lSetPos1=12.34 lSetPos2=100 dSelectMode=1 bWavebusy=0)
通知#3  handle=2  value=(lSetPos1=12.34 lSetPos2=100 dSelectMode=1 bWavebusy=1)
通知#4  handle=2  value=(lSetPos1=10    lSetPos2=100 dSelectMode=1 bWavebusy=1)
通知#5  handle=2  value=(lSetPos1=10    lSetPos2=100 dSelectMode=1 bWavebusy=0)
```

- 回调里 `e.Value` **直接就是 `StAxisInput`**
- **注册时会先来一条当前值**
- 任何成员变化都推**整块** 816 字节

`byte[]` 类型也能订阅，但必须给长度（同 STRING 的规则）：

```
typeof(byte[])             → ArgumentNullException(Parameter 'args')
typeof(byte[]) + args[0]=816 → ✅ 成功，e.Value 是 byte[816]
```

实测字节与写入值一致（写入 23.45 → 开头 `3333333333733740`）。

**通知不基于变量句柄**：可以直接按 IG/IO 注册，完全绕开符号：

```
AddDeviceNotificationEx(0x4020, 405152, settings, "addr", typeof(StAxisInput)) = 0x4
通知#9  handle=4  ...
```

## 七、数组套结构体（`ARRAY OF stAxisInput`）

```
MAIN.arrSt: ARRAY [1..3] OF stAxisInput  ByteSize=2448  IG=0x4020 IO=405968
  arrSt[1]  stAxisInput  ByteSize=816  IO=405968   相对=0
  arrSt[2]  stAxisInput  ByteSize=816  IO=406784   相对=816
  arrSt[3]  stAxisInput  ByteSize=816  IO=407600   相对=1632
```

- **步长 = 结构体 `ByteSize`（816，含填充）**，元素偏移 = 基址 + (i−1) × 816
- 总大小 = 3 × 816 = 2448
- 内存整块读 2448B，与每个元素句柄读的切片**逐字节相同**
- `MAIN.ST1` 基址 405152 + 816 = **405968**，正好等于 `arrSt` 基址（数据区连续排布）
- `ReadAny<StAxisInput[]>` ❌ `Cannot marshal dotnet type 'StAxisInput[]' because its marshal size is unknown!`
  → 整块读 `byte[]` 后按 stride 切，或逐元素 `ReadAny<StAxisInput>`
- 元素能单独建句柄：`CreateVariableHandle("MAIN.arrSt[2]") = 0x61800027`
- 写元素 2 的成员 / 整块写元素 2，邻居元素 1/3 都不变
- 整块写单个元素同样是“覆盖”：旧快照写回会把该元素里期间改过的成员冲掉

```
9.1 写元素2.lSetPos1=55.5 → 读回=55.5；邻居 [10→10] [10→10]
9.2 整块写元素2：lSetPos1=10 lSetPos2=777.7 dSelectMode=9 bWavebusy=1
    邻居 lSetPos1：[10] [10]
```

## 八、内存寻址：结构体和普通数组没有区别

```
结构体 内存读 0x4020/405152 = 816B，句柄读 816B，逐字节相同 = True
MAIN.ST1.lSetPos1: 内存=10  符号=10  相等=True

数组 GVL_AdsDemo.aInts: ARRAY [1..5] OF INT  ByteSize=10  IG=0x4040 IO=408506
  aInts[1] 相对=0 / [2] 相对=2 / [3] 相对=4 / [4] 相对=6 / [5] 相对=8
  内存读 10B，符号读 10B，逐字节相同 = True
```

- **寻址/读写层完全一样**：都是“起始 IG/IO + 一段连续字节”，底层都是 `0xF005`
- **区别只在偏移怎么算**：数组等距（基址 + 索引 × 元素大小）；结构体不等距（成员表 + 对齐填充）
- `IndexGroup` 的差别来自**数据区**，不是类型：`MAIN.ST1` 是 `AT%M*` → `0x4020`；
  `GVL_AdsDemo.aInts` 是普通 GVL 变量 → `0x4040`
- **具体 IO 会随 PLC 工程变化**（同一次测试里加一个变量，`aInts` 从 406058 变成 408506）——
  地址一律以运行时符号表为准，别把本文的数字当常量

## 九、两套句柄

| | 变量句柄 | 通知句柄 |
|---|---|---|
| 实测值 | `0x60000010`（结构体）、`0x61800027`（数组元素） | `0x2`、`0x3`、`0x4` |
| 用途 | `0xF005` 读写 | 标识订阅；`e.Handle` / 删除 |
| 分配 | 符号名 → `0xF003` | 注册通知时服务器分配 |
| 删除 | `DeleteVariableHandle` | `DeleteDeviceNotification` |
| 失效 | 跟连接 / 符号绑定 | 休眠 / PLC 重下程序会**单独作废** |

注册通知的协议参数是 **IG/IO + 长度 + 采样设置**，**不是变量句柄**；
按符号名注册只是让库帮忙把符号解析成 IG/IO。

## 十、时延：整块读写与标量一致

2026-10-18 本机实测（`lat` 模式，句柄 / 内存 / 符号名三条路，单位 ms/次）：

| 对象 | 大小 | 句柄读 | 内存读 | 符号名读 | 句柄写 | 内存写 |
|---|---:|---:|---:|---:|---:|---:|
| `GVL_AdsDemo.lrReal`（标量） | 8B | 1.265 | 1.280 | 1.246 | 1.353 | 1.249 |
| `MAIN.ST1`（结构体） | 816B | 1.353 | 1.292 | 1.257 | 1.322 | 1.215 |
| `MAIN.arrSt`（结构体数组） | 2448B | 1.246 | 1.357 | 1.248 | 1.488 | 1.123 |

**结论：整块读 / 写与普通标量同档（1.1–1.5ms，差值在噪声内）。**
时延由一次往返回路决定，不是由类型或 1KB 级别的数据量决定（>100KB 才开始变化，见 `性能实测.md`）。

**例外是请求次数，不是类型**：

```
MAIN.ST1 逐成员读 36 个：47.120 ms/轮（均摊 1.309 ms/成员）
整块 1 次：              1.289 ms
```

36 倍差 = 36 次往返。换 36 个普通变量逐个读也是同样的代价。

## 十一、没测的

- 嵌套结构体（本工程没有）
- `ARRAY OF STRUCT` 的 `ByteSize` 不是 8 的倍数时，元素间是否额外填充（本工程 816 正好对齐）
- 整块订阅大结构体的带宽 / CPU 开销（只确认功能可用）
- 非 Ex 的 `AddDeviceNotification` 订阅结构体（本文只测了 Ex）
